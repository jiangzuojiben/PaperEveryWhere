# PaperDesk 0.5 在线模式

默认入口为 `CloudWorkspace` / `CloudHome`；网关为 `backend.cloud_main:app`。文献与批注由 ReadPaper 云端保存，自有 AI、翻译和视觉 OCR 使用单独配置的兼容服务。该模式需要联网。

## 启动与连接

1. 在同一 Windows 用户下正常登录 ReadPaper。PaperDesk 只在点击连接后，以只读方式读取必要的现有会话；不操作原应用界面、不自动刷新令牌。
2. 在源码根目录运行 `./scripts/start-backend.ps1`，默认仅监听 `127.0.0.1:8765`。脚本使用项目 Python 环境；首次缺少环境时安装依赖，写入的是程序环境而非业务数据。
3. 使用本轮 `PaperDesk-0.5.0-Windows-cloud.zip`，在“云端连接与自有 AI”点击“使用本机已登录的 ReadPaper”。登录成功后从云端读取文献及文件夹，按需打开 PDF。
4. 在同一设置页填入自有 AI/翻译基础地址、模型及 Key；只在本次会话有效。OCR 使用自有视觉模型，无需 ReadPaper AI 权限或 AI 豆。缺少配置时任务明确失败，不自动改用 ReadPaper AI。

Android 当前通过跨设备连接码接入同一个网关。在 Windows 已连接会话中创建连接码，再在 Android 输入网关 HTTPS 地址与该码。连接码120秒内单次有效；新设备获得独立内存会话，不复制自有 AI Key。网关若向手机开放，应通过受信任证书的 HTTPS 反向代理；本机 Cookie 读取接口拒绝外部请求、Origin 和转发身份头。脚本默认的回环监听不直接向局域网开放。原生 Android ReadPaper 登录及独立跨设备扫码授权尚未适配。

当前默认启动脚本适用于 Windows 本机网关。原 `compose.yaml` 是0.3本地优先部署，不能当成本轮在线模式部署；其数据库、Redis和对象存储均不在新网关调用链。新的只读容器定义为 `compose.online.yaml`，其中不提供 Windows 原应用会话引导，不能据此宣称容器登录链已完成。

## 数据生命周期

- 新默认客户端不初始化 SQLite、SharedPreferences 或安全存储；旧数据库和导出迁移包保持原样，既不自动载入也不删除。
- 连接时读取文献列表和分类到内存。打开文献时网关取得新文件地址，用独立、无账号头的 CDN 客户端下载 PDF 到内存，验证 PDF 并计算版本哈希。仅允许两个已确认的 ReadPaper PDF CDN 主机，不跟随重定向。
- 当前文献的正文、原批注、进度和笔记进入会话内存。Flutter 使用 `PdfViewer.data`，没有使用 URI 磁盘缓存；会话全文索引也是内存映射。缩略图及 AI 图像只在内存处理，释放时清理 Flutter 图像缓存。
- 修改不进入持久 outbox。等待云端成功响应并读回核对批注、笔记及进度，才更新已保存状态；删除须确认读回列表已无该批注。读回不匹配或超时表示结果未知，不自动重试创建；用户应先刷新核对，避免重复批注。
- 阅读页刷新会先保存当前笔记和进度，再读取最新云端批注和阅读笔记；保存失败会中止刷新并保留草稿。PDF版本变更需退出后重新打开。
- 退出阅读页前尝试保存笔记和进度；失败时继续保留当前内存草稿，用户可继续编辑或明确放弃退出。关闭阅读页后释放对应 PDF、正文、笔记、批注和 AI 结果。退出账号时立即清理客户端状态并撤销网关会话；即使撤销请求失败，也不会恢复本机数据。
- 网关会话、ReadPaper Cookie、自有模型 Key、任务输入和结果均只在内存。空闲30分钟过期，每30秒清理一次，进程退出清空。没有 PostgreSQL/SQLite/Redis/S3 依赖。正在执行的外部模型调用最多等待其60秒网络超时；取消/退出后结果不再发布。
- 应用日志不含 Cookie、签名 URL 或上游响应正文，API响应使用 `Cache-Control: no-store, private`。默认脚本关闭 HTTP 访问日志。软件依赖、字体/引擎资源及此前独立备份不属于会话业务副本。

## 上传与版本

在文献库右上方“上传PDF”选择文件。Windows只读取用户所选原文件，不创建副本；Android使用自有SAF通道从ContentResolver流读入内存，没有使用file_picker的Android缓存复制路径，也不保存URI长期授权。Android导入上限64MB，Windows及网关上限256MB。文件选择期间切换账号会拒绝继续上传；已排队操作同样绑定发起时会话，不能转入新账号。

网关使用原始 `application/pdf` 请求流，避免UploadFile/multipart解析器将内容落到临时文件。验证文件后调用ReadPaper预检、上传和创建状态查询。上游multipart请求由内存字节构建；上传凭据、处理令牌和操作记录只在网关会话内存，前端不收到原令牌。上传不自动重试；不确定结果可在“本次上传”核对或刷新文献库。冲突需要显式保留原件或替换选择，取消也需云端确认。

在文献行菜单打开“云端版本管理”。仅展示ReadPaper返回的PDF版本，不把外部链接当文件。选择前再次核对版本属于该论文，调用原生选择接口并确认当前版本标记，再按docId关联文献。索引PDF可能尚未变化；打开时另行调用getPdfStatusInfo/v2获取所选文件的访问许可和下载地址，防止沿用笔记接口的旧URL。批注和进度重新从云端读取，ReadPaper可能跨版本复用noteId和批注，界面提示原坐标可能不匹配。独立上传PDF（paperId为-1/0）没有论文版本集合，显示限制，不制造本地版本历史。上传“此论文的新版本”使用ReadPaper的匹配验证场景，是否合并由上游判定；不匹配或冲突不能冒充版本已建立。临时收录的公开论文已完成真实选择、匹配新版本上传以及独立第二会话SHA-256核对，之后恢复选择、清理测试批注并取消收录。

## 本轮能力与限制

| 项目 | 状态 |
|---|---|
| 文献清单、层级文件夹 | 已实现；原账号88篇、30目录；新增2份可识别的云端合成验证PDF |
| PDF与原批注读取 | 已实现；实测一份7页文献和原高亮，测试目录零运行时文件 |
| 文字高亮、矩形、文本框新增/修改/删除 | 已在专用测试文献真实执行并读回，第二独立会话恢复确认；测试批注已清理 |
| 原图形与未适配批注 | 支持矩形/箭头、已知webDrawV2笔迹路径及变宽显示/删除；复杂擦除/剪裁页不绘制未擦除残留，给出提示。原生手写与直线创建工具暂不展示 |
| 阅读笔记 | ReadPaper 每篇一份阅读总结，Markdown正文直接写回；新建多条笔记、改标题和本地导出不在本模式提供 |
| 阅读进度 | 云端读取/保存已真实验证，测试笔记和进度已还原 |
| 自有问答、摘要、翻译、图表解读、视觉OCR | 独立内存任务路径；模拟模型验证了来源、账号隔离及释放，无真实服务Key，质量未验收 |
| AI上下文 | 默认前20页；单页50000字符、问答总100000字符，结果标记截断，界面不将部分处理称为全文完成。OCR按当前页执行 |
| PDF上传 | 真实上传、重复去重、独立会话下载哈希验证通过；状态/取消/冲突及不自动重传有契约测试 |
| 云端版本 | 原生列表、真实选择及匹配新版本上传通过，第二会话字节核对通过；上游可跨版本共享批注，提示坐标需核对 |
| 附件上传、资料/标签/目录写入、批量管理 | 尚未接入；当前账号附件上传预检明确要求标准版，没有绕过或用附件侧存手写 |
| 离线阅读/离线编辑/本地导出/持久任务历史 | 新默认模式不提供 |

笔记/批注写入前重新读取来源内容指纹，防止已知旧版本覆盖；ReadPaper 原子条件写入尚未得到验证，多个原客户端同时提交仍可能在检查与写入间竞争，不能宣称已实现完整跨端并发无丢失。新模式暂禁用旧撤销/重做，避免假定云端能恢复原批注ID。

## 验证

`backend/tests/test_cloud_bridge.py` 用模拟ReadPaper服务验证请求、坐标、写入确认、并发检查、源身份、CDN隔离、只读原Cookie库、连接码、退出和过期。测试目录没有产生业务文件。`client/test/cloud_workspace_test.dart` 拦截本地存储插件调用，验证零调用、云端确认前不改快照、失败状态、迟到响应丢弃、退出和新会话为空。

0.4仅执行只读检查，记录为 `artifacts/cloud-readonly-verification-20261023.json`。0.5新增专用合成文献的真实写回及上传检查，记录为 `artifacts/cloud-live-basic-20261023-attempt1.json` 、`artifacts/cloud05-live-upload-20261023.json` 和 `artifacts/cloud05-live-versions-20261023-attempt6.json`。原88篇文献及分类关系未变。桌面界面、Android新模式模拟器、手机实机及真实模型调用均未执行；不能把本轮构建当作这些验收已通过。

本轮测试命令：

```powershell
./.venv/Scripts/python.exe -m pytest backend/tests -q
cd client
flutter analyze --no-pub
flutter test --no-pub
```

网关必须单进程运行，多worker会导致内存会话路由失败。实例重启后须重新连接并配置自有服务。

当前接口契约为 `docs/openapi-online.json`；`docs/openapi.json` 保留0.3版本历史契约。接口文档也可在新网关运行时访问 `/docs`。
